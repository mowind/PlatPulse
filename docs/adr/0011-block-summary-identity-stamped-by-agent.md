# ADR 0011: A Block Summary's Network Identity is Agent-side evidence stamped at Block Resolution; a Node identity change is remedied by restarting the Agent, and Identity-Mismatch history is never backfilled

- **Status:** Accepted. The diagnostic refinement in Decision 4 is implementation pending (issue #235).
- **Date:** 2026-10-10

A Block Summary carries the Network Identity of the chain its Agent resolved it from, and the Server terminally rejects any sample whose stamped identity differs from the registered Network (design §4.5, §13.2; `crates/platpulse-server/src/http/report_ingestion.rs:696`, `:716-728`, `:2939-2943`, `:2969-2972`). That identity is not read from the block: it is the `NetworkIdentity` the Block Worker held when it resolved the block (`crates/platpulse-agent/src/block.rs:260-274`, stamp written at `crates/platpulse-agent/src/block.rs:271`), refreshed only when the worker re-enters its outer loop (`crates/platpulse-agent/src/collector.rs:1791-1820`). Because the WebSocket provider reconnects transparently (`crates/platpulse-agent/src/block.rs:210-211`), a Node that changes its own identity does not surface a transport error, so the Agent keeps stamping the old identity while its component-level Network Identity observation is already fresh and matching (`crates/platpulse-agent/src/collector.rs:685`). On 2026-10-10 this produced a self-contradictory state on the `Centaur` Node: the identity was matched and the critical `node.network_identity_mismatch` incident had resolved, yet every block sample was `terminal_rejected` for a further 11 minutes, `block_summaries` stayed empty and Home rendered `Txs = Unknown` (issue #235, follow-up of #234). This ADR records the semantics that follow from that investigation.

## Context

- **The stamp is per-sample evidence, not a projection.** The Server compares the four identity fields on the sample itself against the Network Registry row for the Node's Network (`crates/platpulse-server/src/http/report_ingestion.rs:716-718`, `:722-728`); a single differing field marks the Node and every sample of it in that Report is rejected (`crates/platpulse-server/src/http/report_ingestion.rs:2930`, `:2939-2943`, `:2969-2972` with reason `"Block network identity does not match the registered Network"`). Component observations of the same Report are unaffected — `network_identity` was `accepted` in the very receipts whose block samples were rejected.
- **The Agent stamps, it never re-reads.** `crates/platpulse-agent/src/block.rs:260-274` `fn resolved_from_block(&self, block: PlatonBlock, identity: &NetworkIdentity) -> Result<ResolvedBlock, TransportError>` copies the caller's identity verbatim at `:271`; `crates/platpulse-agent/src/block.rs:533-543` `resolve_live_head(&self, subscription: &LiveHeadSubscription, node_id: NodeId, header: &HeadHeader, identity: &NetworkIdentity, observed_at: Rfc3339)` and `crates/platpulse-agent/src/block.rs:1233-1268` `resolve_next` only pass it through (the `:1249` identity comparison is same-source and therefore cannot fail).
- **The Agent's identity source for that stamp is its own last persisted Report.** `crates/platpulse-agent/src/collector.rs:1755` `run_node_block_worker` reads `item.chain.network_identity.latest.clone()` from `load_last_report` (`crates/platpulse-agent/src/collector.rs:1791-1820` → `crates/platpulse-agent/src/collector.rs:601-633`, backed by `agent_state.last_report_body`, written every collection cycle by `crates/platpulse-agent/src/reporting.rs:886-904`), then reuses that value for the whole `'connected` loop (`crates/platpulse-agent/src/collector.rs:1866-1955`, resolve at `crates/platpulse-agent/src/collector.rs:1874`). Only a transport error (`crates/platpulse-agent/src/collector.rs:1918-1930`) returns the worker to the top of the outer loop.
- **The Registry is validated, never rewritten.** "An Agent declares a Node's configured Network key and observed identity, while the Server validates them without automatically rewriting the registry" (CONTEXT.md, *Network Registry*); *Network Identity Mismatch* keeps diagnostics running but forbids merging block history into the registered Network. Design §6.2 restricts Gap Backfill to an open recoverable gap.
- **A Node build upgrade is an identity change.** #234: builds before `45c3e086d` answer `eth_chainId` with the legacy `ChainID` (`100`) instead of `PIP7ChainID` (`210425`), so upgrading a Node's binary silently changes the identity its Agent observes.

## Decision

1. **The stamped identity stays the only per-sample authority.** The Server compares the stamp on each Block Summary with the registered Network and terminally rejects on any difference. It never re-labels, migrates or accepts a sample on the strength of a matching component observation, and it never rewrites the Network Registry to agree with a Node. A sample that was rejected stays rejected.
2. **The stamp's refresh boundary is the Block Worker's subscription; the remedy for a Node-side identity change is an operational restart of that Host's Agent.** A Node whose own identity changes (build upgrade, or a genuine Network move) must have its `platpulse-agent` restarted so the worker re-reads the identity and re-subscribes. Editing the Registry is never the remedy: #234 showed that matching the legacy tuple would immediately mark the other six Nodes mismatched. Until that restart, the correct state is "diagnostics healthy, block history rejected" — not "history accepted under a stale identity".
3. **Identity-Mismatch rejections leave permanent holes that stay visible as holes.** A `server_rejected` History Gap (`crates/platpulse-server/src/http/report_ingestion.rs:2797-2801`) never opens a coverage interval — only `GapKind::UnrecoverableBackfill` calls `open_coverage_gap` (`crates/platpulse-server/src/http/report_ingestion.rs:2817-2827` → `:565-587`, `block_coverage_intervals.status='open_recoverable_gap'`) — and later backfill for those heights stays refused by `GapBackfillOutsideOpenGap` (`crates/platpulse-server/src/http/report_ingestion.rs:2951-2955`). We keep it that way: those intervals must render as gaps and must never count as covered history, because the whole point of the stamp is that history is attributable to a Network at the time it was accepted, and a span during which no sample of that Node was attributable must not later read as continuous. Granting the tail of a rejected run a retroactive recoverable interval requires a new ADR.
4. **A per-sample rejection must say what actually differed, and point at the remedy.** The receipt reason must name the differing field(s) with observed and registered values, and distinguish "the Agent's stamp is stale — restart the Agent on that Host" from a genuine cross-Network conflict; the divergence between the fresh component Network Identity observation and the stamped samples must be visible where operators look, so that "identity matched, incident resolved, history fully rejected" is never an ambiguous operator state again. (Implementation pending, issue #235.)

## Considered options

- **Server re-labels or accepts the sample when the component observation matches.** Rejected: the Server would accept chain data it cannot attribute to a registered Network per sample, and a genuinely cross-Network Agent would be silently merged instead of refused.
- **Re-key the Network Registry (or add a legacy alias Network) when an upgrade changes the observed identity.** Rejected: contradicts "the Server validates them without automatically rewriting the registry" (CONTEXT.md) and, for the #234 tuple, would invert the mismatch onto every other Node.
- **Leave restart as an undocumented implementation detail.** Rejected: it produced exactly the ambiguous 11-minute state above, with a healthy-looking identity and a completely empty Block History; the runbook belongs in `docs/deployment.md`.
- **Reopen the tail of a `server_rejected` run as an open recoverable gap once identity matches again.** Rejected for now (Decision 3). Weaker than it looks: the Agent deletes each rejected Block Summary from its Store on receipt application (`crates/platpulse-agent/src/collector.rs:2586-2593`), so the Agent would have to re-resolve the whole span from its own Node, i.e. a different operation from Gap Backfill's bounded reconnect recovery.
- **Keep the generic rejection reason.** Rejected: the reason is the only evidence a receipt carries about a data-producing failure, and "does not match the registered Network" cannot be acted on without knowing whether to restart an Agent or investigate a Network move.

## Consequences

- **Verified field outcome (2026-10-10, Node `Centaur` `0ec86838-6e5a-4526-ab43-94e345c1969a`, Agent `edf2f460-1af8-4834-a564-0313bd9a3849` "Aliyun SG"):** the Node was rebuilt and restarted at `2026-10-10T09:23:05Z` (pid 78159) but every block sample stayed `terminal_rejected`; the Agent restart at `2026-10-10T09:34:53Z` (boot `8fd45467-0132-43f1-ab78-98b9e3065df3` closed, `5e90f489-abb5-4796-b74e-135c0d379389` active) healed it immediately — the new boot's first Report still carried one stale-stamped block (`160868244`) and was `partially_accepted`, and every Report from sequence 2 on was `accepted`. `block_summaries` went 0 → 29 (`160868245`…), coverage interval 30640 (`160868245`..`160868282`, `covered`), and `latest_block_transaction_count` went NULL → 0.
- **The user-visible symptom of a rejected data plane is `Txs = Unknown`, not an error.** `crates/platpulse-server/src/http/public.rs:2880` (`bs.transaction_count AS latest_block_transaction_count`) with the `LEFT JOIN block_summaries` at `crates/platpulse-server/src/http/public.rs:2917-2918` yields NULL whenever a Node has no accepted Block Summary; `platpulse-web/src/components/HomeDashboard.tsx:846`/`:924` and `platpulse-web/src/pages/HomePages.tsx:114`/`:209` render it as Unknown. Component health and Block History health can therefore disagree completely; both must be read.
- **The trigger case leaves a permanent hole.** Node `Centaur`'s Block History will never contain `160866429`…`160868244`: 1816 consecutive heights (09:02:53Z–09:34:53Z, ~32 minutes) recorded only as `server_rejected` History Gaps.
- **The Agent's own local retention does not help.** Block Summaries rejected by the Server are deleted from the Agent Store on receipt application and replaced by a local `history_gaps` row (`crates/platpulse-agent/src/collector.rs:2570-2638`, delete at `:2586-2593`, `server_rejected` insert at `:2630`), so a rejected span is not recoverable by replay from the Agent.
- **Follow-ups** (all tracked by issue #235): the §4 diagnostic refinement; the restart runbook in `docs/deployment.md`. The CONTEXT.md wording pass landed with this ADR and is not an open item.
- Design §4.5, §6.2, §13.2 and the CONTEXT.md *Network Identity* / *Network Identity Mismatch* / *History Gap* / *Gap Backfill* entries keep their current meaning; this ADR adds the refresh boundary and the no-backfill decision rather than changing them.
- **Glossary: CONTEXT.md gained the term this ADR is named for**, plus amendments to four existing entries: *Block Identity Stamp* (new), *Block Summary* (the stamp is per-sample evidence), *Network Identity Mismatch* (binding point and restart remedy), *History Gap* (an identity-rejected interval never opens a coverage interval and is never backfilled).
