### 15.37 Home Balance tile: the Reward Wallet Balance replaces the Networks counter (issue #246, delivered)

Applies to `PAGE-HOME-NETWORKS` (`/`), on top of §15.28, §15.29 and §15.36. Node Detail is unchanged: its `OverviewBand` carries its own six key metrics.

- **What it reads.** The tile titled `Balance` (wallet icon, the band's green tone) shows the Reward Wallet Balance (`CONTEXT.md`): the freely available native balance of the fixed Reward Wallet `lat1zyctwgvw3ssagn722cneh6sz92y8j3dp8gqj5h` on PlatON mainnet, as PlatScan's `address/details` reports it in `data.balance`. It is not Validator Lifetime Rewards, and it excludes restricted, staked, delegated and unclaimed-reward amounts; none of those PlatScan fields is shown. A decrease is an ordinary account movement, not a Counter Reset or Correction.
- **Why the address is fixed.** The Reward Wallet is a property of this deployment, not something an Owner, an Agent or a reader chooses, so the address and the PlatScan base URL are Server source constants (crates/platpulse-server/src/reward_wallet.rs): not in `server.toml`, not editable from Admin, never reported by an Agent and unrelated to `[validator_provider]`. Changing it is a code change, which keeps the Public figure from ever pointing at an address nobody reviewed.
- **How the Server keeps it.** A background refresher asks PlatScan once a minute with a 10-second timeout, independent of Home traffic; a failure waits for the next cycle. An HTTP error or timeout is `upstream_unavailable`; `code != 0`, a missing `data.balance` or anything but a non-negative decimal string is `invalid_response`. A failure only moves the attempt time and the category and never overwrites the last-good balance, which is stored as its exact decimal string in one SQLite row (migration 0074) and survives a restart. Raw upstream errors reach the Server log only. Development mode starts no refresher, so local runs and the e2e suite never contact PlatScan (`e2e/start-server.sh` writes the row directly).
- **Public reading.** `GET /api/public/v1/reward-wallet` is a Public Projection route that follows the Site Access Mode like `/networks` (Guests in Public mode, an Owner or Viewer Session in Private mode). It returns `address`, `balance` (absent until a refresh succeeds), `unit: "LAT"`, `state` (`current`, `stale` once the last success is more than three minutes — three refresh cycles — old, or `unavailable` when no refresh ever succeeded), `lastGoodAt`, `lastAttemptAt` and `errorCategory`. A committed change of the row publishes the Public `reward_wallet` Invalidation Event; a rolled-back write publishes nothing. Every attempt moves `lastAttemptAt`, so a running refresher invalidates once a minute even while the balance holds: that one refetch per minute per Home is deliberate, because it is what carries the time-driven `current` → `stale` change and the tile's stale age to an open page. The browser never contacts PlatScan and the CSP stays `connect-src 'self'`.
- **States on the tile.** Current: `138,179.54 LAT` (grouped, two fractional digits truncated from the source digits, never rounded up) over `Mainnet · lat1zy…j5h`; the full address, the exact balance (`138179.543005858536 LAT`) and the last success time are in the reading's `title` and the tile's accessible name. Stale: the last-good value stays, the caption reads `stale · <age>`, and the title names `PlatScan unavailable` or `PlatScan returned an invalid response` with the last success time. Unavailable: `—` over `Unavailable`, never `0`. While its own request is loading the tile reads `—` over `Loading…`. There is no external link and no Breakdown.
- **Independent of every selection.** The tile is fed by its own TanStack Query, so the Network selection, the search, the Health and Validator status filters, an empty `No match` list, and a loading or failed `/networks` request change nothing it shows. The three counters that follow the list are now Active Nodes, Healthy Nodes and Attention.
- **Order.** Active Nodes, Healthy Nodes, Attention, Balance, Cumulative blocks, Cumulative rewards — three columns by two rows from 640px and two columns by three rows below it, with DOM order equal to visual order.
- Acceptance. crates/platpulse-server/src/reward_wallet.rs (mock PlatScan: success, `code != 0`, missing and malformed balances, timeout, HTTP errors, last-good retention, never-succeeded, stale after three minutes, restart, rollback publishes nothing, development mode sends no request), crates/platpulse-server/src/http/mod.rs (`reward_wallet_follows_the_site_access_mode`), platpulse-web/src/components/RewardWalletCard.test.tsx, platpulse-web/src/components/HomeDashboard.test.tsx, and the Playwright specs home-overview-layout, home-search-filters, home-convergence, home-geo-map and shell across the five fixed projects.

### 15.39 Home Node Card Staggered Entrance Animation (issue #278, delivered)

Applies to `PAGE-HOME` (`/`), on top of §15.23, §15.24, and §15.27. Visual reference: `komari-theme-emerald` `HomeView.vue` (`.node-card-switch-enter-active`); register entry: Emerald deviation 43 (`docs/visual-migration/emerald/deviation-register-28-43.md`).

- **Interaction and triggering.** Switching Network pills or modifying search, Health, Validator-status, Sort, or view filters updates the grid remount key (`${scope.network}:${writeHomeFilters({ ...filters, network: scope.network }).toString()}`), cleanly triggering the staggered entrance animation without manual data clumping. Only such a change animates: the first grid Home shows — on page load, after the projection finishes loading, or on returning from a Node — appears at rest, as Emerald's switch transition does not run on appear. `HomeDashboard` marks a remounted grid `data-entrance="stagger"` and the keyframes bind only under that attribute.
- **Timing and easing.** Each card entrance animates over 220ms with easing curve `cubic-bezier(0.22, 1, 0.36, 1)`. Stagger delay is calculated by `nodeCardStaggerDelay(index)` in `components/nodeCardStagger.ts` as `Math.min(index * 25, 250)ms`, providing a sequential entrance across cards while capping maximum delay at 250ms (within the 200~300ms design window) so long lists do not feel sluggish.
- **Transform and layer integrity.** Keyframe `node-card-enter` starts at `opacity: 0; transform: translateY(8px) scale(0.985);` and transitions to `opacity: 1; transform: translateY(0) scale(1);`. The animation uses `animation-fill-mode: backwards` so that during the stagger delay the element is hidden and offset, but once the animation completes the transform is released to `none`. This prevents `[data-slot='node-card-frame']` from retaining an active transform at rest, preserving the root stacking context required for `hover:z-1` elevation and tooltip positioning (§15.27).
- **Reduced motion.** Strict compliance with `prefers-reduced-motion: reduce`: animation is disabled (`animation: none !important; transform: none !important; opacity: 1 !important;`) in `platpulse-web/src/styles/emerald.css`, rendering cards immediately at rest without layout shift or transition delays.
- **Acceptance.** Unit and DOM styling verified by `src/components/HomeNodeStagger.test.tsx` (delay formula, cap, negative handling, filter and network recalculation, scoped grid assertions, first grid at rest and staggered remount, keyframes, `backwards` fill mode, and reduced-motion rules). Fixed-viewport geometry contracts measure the page at rest (`waitForAnimationsToSettle` in `e2e/helpers.ts`).
