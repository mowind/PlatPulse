### 15.26 Home latest-60-second charts drawn from the Server's own coverage, never across a silence (issue #225, delivered)

Applies to `PAGE-HOME-NODE` (`/nodes/:nodeId`), on top of the accepted six-chart deck of §11.1 (issue #150) and of the gap doctrine the Admin long-history panel reads in §15.16, and to the Public latest-60-second response those charts draw from:

- The chart's question is answered by the Server, not guessed by the browser: `GET /api/public/v1/nodes/{node_id}/metrics` now carries `series`, one `PublicMetricSeriesCoverage` per plotted direction, in the same order as the nine arrays it judges (`PUBLIC_METRIC_SERIES`, crates/platpulse-server/src/http/public.rs:1440, whose entries are the camelCase response field names the nine arrays do not carry themselves). The change is additive: `from`, `to`, `windowSeconds` and the nine arrays are untouched, the window stays 60 seconds (`PUBLIC_NODE_METRIC_WINDOW_SECONDS`, crates/platpulse-server/src/http/public.rs:1185), no Admin route or panel changes, and no Audit entry is written, because this answer observes nothing and commands nothing.
- What one series can vouch for, as `PublicMetricSeriesCoverage` (crates/platpulse-server/src/http/public.rs:1234-1285): `observed` (whether this answer carries any observation of the series at all, including the last-good point that precedes the window), `neverObservedProven` (whether that `false` is a proof that nothing was ever recorded, or only that the Server holds no evidence any more), `observationCount` (window only, so a series that is observed but counted zero has not been seen recently and the tail dates that rather than a zero), `firstObservedAt`/`lastObservedAt`, `cadenceSeconds`, `gapThresholdSeconds`, `coveredSeconds`, `unobservedTailSeconds`, and `gaps` — `PublicMetricGap { from, to, seconds, kind }` (:1215-1232), `from` the newest instant before the silence, `to` the first observation after it, which is exactly where a chart may start drawing again, and `kind` today always `collection_gap` from the shared `GapKind::as_str` vocabulary, because a 60-second answer holds no protection pause to name. `coveredSeconds` never counts the stretch after the newest observation, because nobody observed how long it is, and `unobservedTailSeconds` measures from the newest observation to the end of the window and may exceed the window when that observation is an older last-good point: the series really has been quiet that long. A series whose raw samples retention has already removed is still a series somebody observed, so the Server dates it from the series ledger (`node_metric_series_state`/`host_metric_series_state`, migrations/0066_node_metric_history.sql:42-54 and migrations/0068_host_metric_history.sql:83-97), which holds the first and last observation instant of every metric and no value at all: the Public answer gains an age without gaining a fabricated point, and only a metric the ledger never saw answers `observed` false, which `neverObservedProven` qualifies: it is true for the seven series stored under a metric name, whose ledger row outlives the samples retention prunes, so their absence is a proof that nobody ever reported them, and false for the two block series (`blockIntervalMs`, `transactionCount`) — a limit this contract states instead of hiding: they live in `block_summaries`, which has no ledger beside it, so once retention removes their rows the Server can neither date that expiry nor tell a series that went quiet long ago from one nobody ever reported, and it answers them as an unknown rather than as never observed; dating them would need a block-series ledger, that is new schema outside this ticket, while nothing is invented either way (no zero, no line, `Unknown` rather than 0).
- An unknown cadence is never read as silence. `cadenceSeconds` is the cadence currently in force — the newest interval between two consecutive observations, adopted as it stands when it is the only interval there is and trusted while the interval before it agrees with it within a factor of two — and `gapThresholdSeconds` is three times it, capped at five minutes of cadence. Zero cadence means the Server holds no rhythm verdict for that series and it then answers `gapThresholdSeconds` 0 with no gaps, so a series with no known rhythm is answered as unknown instead of as silent — the same rule §15.16 states for a series with no self-measured cadence. Zero is also the honest answer immediately after an interruption, because the interval before the newest one is the interrupted one: two intervals that disagree by more than a factor of two cannot tell an interrupted collection from a cadence that legitimately changed, so the answer names no silence and `coveredSeconds` stays 0 until the next observation settles the rhythm — a series observed every 5 seconds, silent for 30 seconds and then resumed for two intervals answers cadence 5 with the gap, because by then the interval before the newest one agrees with it.
- The Server did not write a second gap rule: the metric-history machinery was reused with its silence floor made a parameter (`gap_threshold_seconds_with_floor`, crates/platpulse-server/src/metric_history.rs:766, and `continuity_with_floor`, :819, both feeding `silence_threshold_seconds`, :927). The Admin surfaces keep `gap_threshold_seconds`/`continuity` with `MIN_GAP_SECONDS = 120` (:360), so the Admin long-history panel and its assertions are unchanged; the Public 60-second answer passes a floor of 0, because a two-minute floor sits above the whole window and no silence inside it could ever be named. The cadence behind the verdict is the current-cadence rule (the newest interval) rather than the fastest-gap rule the Admin aggregate tiers use, so ordinary jitter is not read as silence. The last-good point that precedes the window still rides as element 0 of its array and still informs the value, the cadence and the age shown, but it never enters the continuity computation: a silence that begins before the window is not a gap in it.
- The client seam is platpulse-web/src/metricCoverage.ts, a thin reader of that contract rather than a second chart framework: `metricCoverage(history, metric)` finds one series' own verdict, `coverageSegments(points, from, to, gaps)` cuts the window's observations into runs at the silence the Server measured and answers every surviving sample in the Server's own units and at the Server's own instant (`MetricObservation { sampledAt, value }`), and `coverageNote`/`coverageNotes` write the sentence. The seam deliberately carries no pixel projection: the deck draws a real time axis with the Server's values since the ECharts port of §11.1 item 8, so the geometry that used to live here is now asserted where it is produced. The Admin plot's `metricChartGeometry`/`metricLineRuns` in platpulse-web/src/metricHistory.ts were deliberately not reused: they fold the Admin answer's stored observations and aggregate buckets into at most 120 columns that keep each bucket's minimum and maximum and a hole the client proves from its own bucket cadence, while a Home chart reads raw observations the Server has already judged. Reusing the bucket geometry here would have made the client re-derive a silence the Server has already decided — two rules for one contract.
- The chart draws only what was observed (platpulse-web/src/pages/HomePages.tsx `NodeMetricCard`, drawn by platpulse-web/src/components/NodeMetricChart.tsx since the ECharts port of §11.1 item 8 — deviation 28 in the Emerald register). An observation outside the window is dropped rather than clamped onto an edge: the previous `chartCoordinates` clamped the single pre-window last-good point to x=0 and then extended it to x=600, and that fabricated tail is what this ticket removes, so a line now stops where the observations stop and the area fill ends with it. A run is broken exactly where the Server named a silence — the segment ending at the last observation before it and the segment starting at the first observation after it are both drawn, and nothing is connected across the hole and no zero is filled into it. An isolated observation stays visible as its own run (a single-point run draws a marker sized per direction since the port: r 4 for the card's first direction and 3.5 for the next ones, so a partner's isolated point is not read as the primary one's) instead of collapsing into a one-point path. Nothing else about the deck moved: the grid, the legends, the toolbar, the disclosure, the real 60-second window and the empty state's own sentence (`No samples in the last minute`) all read as §11.1 accepted them, and an empty series still draws no line rather than a line at zero. The run/break rules are unchanged by the port; only their rendering is. The seam still holds one source of truth but no longer speaks pixels: the earlier `coverageRuns(points, from, to, max, gaps)` mapped samples into this ticket's 600×150 hand-drawn viewBox, and once the deck draws a real time axis of the Server's own values that projection had no consumer left, so it was replaced by `coverageSegments` — a recorded departure from decision B's letter that keeps its intent — and the geometry is now asserted where it is produced instead of through a path `d` (the hand-drawn SVG marks this ticket's tests measured are gone): platpulse-web/src/components/nodeMetricChart.test.ts measures per-sample positions, break points and marker sizes against expectations computed independently from the option's own grid, and platpulse-web/src/components/nodeMetricChartOption.test.ts asserts the option itself. One rendering consequence belongs here, because it is about the same window: ECharts 6 widens a time axis by half a bar's bandwidth whenever a bar series shares it (`containShape`, on by default), which pulled the two block charts' edges inward and made them disagree with the four lines about the very window the Server answered; the bar variants therefore set `containShape: false` (platpulse-web/src/components/nodeMetricChartOption.ts), accepting that an observation exactly on `from` or `to` is clipped to half a bar at the plot edge instead of moving the whole window.
- The card says what the curve cannot, without drawing a line of small print for it. Since the refinement round's follow-up no card renders a visible coverage paragraph at all: the sentence is written once, into the chart's own `sr-only` accessible description, which the `data-slot="node-metric-chart"` container points at through `aria-describedby`, so a reader using a screen reader still hears what the curve cannot show. Only that paragraph went — the card's `detail` line (a last-good value's age, the block heights a bar spans), its italic `Upload unavailable in this window` direction note, and its empty state all stay exactly where they were, and the vocabulary below is unchanged: `No samples reported yet` for a series nobody observed, which the card says only where the Server can prove that absence (`neverObservedProven`), `No retained observations` for one whose absence the Server cannot prove either way — the two block series, whose only record is `block_summaries` and whose rows retention removed, read as an unknown and never as a claim that nobody reported them — `Last observation 2 minutes ago` for one whose window holds nothing while the series has been seen before it (which is also how a ledgered series reads once retention removed its samples: dated by the ledger, so an age, never `No samples reported yet`), `1 gap in this window` / `3 gaps in this window` for silences the Server counted, and — only when the tail is at least as long as the decided threshold, so the age is a named silence rather than ordinary waiting — `No samples for the last 4 minutes` joined to it with ` · `. A card that plots two directions (Host network's Upload/Download, Peer connections' Inbound/Outbound) writes one sentence when both directions agree and names them when they do not (`Upload: 1 gap in this window · Download: No samples for the last 2 minutes`), and writes nothing at all when there is nothing to say, a response without `series` included — which is why every earlier fixture and assertion, Admin included, still holds. Durations reuse the metric-history wording (`formatHistoryDuration`: `1 minute`, `20 seconds`), so one age is spelled one way on both surfaces. That sr-only paragraph is the sentence's only home now: the container carries `role="img"` and `aria-describedby` pointing at it (the ECharts canvas no longer exposes an `svg[role="img"]`), and the tests read the sentences back through those ids instead of through a visible slot. The card's footer is therefore as quiet as the deck it is ported from — a card with nothing else to report draws nothing between its header and its plot, so the plot's start no longer depends on whether a sentence happens to be there — while the notice remains text, never a colour or a symbol alone, and the statement the deck used to make twice — printed under the title and read aloud — is written exactly once.
- Later amendment — live refresh keeps the reader's legend choice and never disguises a failed refresh (Node Detail closing refinement, after #225; the shared `InfoHint` pattern that refinement introduced is specified in §11.1 item 5, so the no-new-pattern statement below covers #225 itself). Every option the deck draws is still applied with `notMerge`, so a run that left the window is removed rather than merged into the next answer and a silence is never bridged; the reader's own legend choice is restated on each apply instead (`withLegendSelection`, platpulse-web/src/components/nodeMetricChartOption.ts, fed by the instance's `legendselectchanged` event in platpulse-web/src/components/NodeMetricChart.tsx). Because all runs of one direction share its legend name, hiding Upload, Download, Inbound or Outbound hides every run of that direction, survives data refreshes, resizes and Light/Dark switches, and is kept while the direction has no samples. Each chart holds its own choice, and the deck is keyed by Node so another Node starts with every direction shown. When the metrics refresh fails after an answer was drawn, the cards keep that answer — its own `from`/`to`, samples, coverage, gaps and missing directions — and the deck heading reads `Retained 60-second window` with one short `History update failed · Showing previous window` notice and an info hint carrying the retained window's UTC bounds; each chart's accessible name says it covers a retained window. A first failure with nothing drawn keeps the per-card `Metric history unavailable` state, and the notice clears with the next successful refresh. The Block interval tile is judged by the block-summary query alone: a failed refresh keeps the last interval and appends `Block history update failed`, and a first failure reads `Block history unavailable` rather than claiming two summaries are missing.
- This ticket adds no route, no navigation entry, no pattern and no new acceptance family: the behaviour lives inside the already accepted six-chart deck of `SCN-HOME-NODE-DETAIL`, so no `PAGE-*` and no `SCN-*` reference changes. The shortcut of impersonating a device by zooming a jsdom viewport is still ruled out: jsdom asserts the contract (which observations become which runs, where a run breaks, and which sentence the chart's description carries) while the real geometry is asserted in the browser at the five fixed viewports in both themes.
- Acceptance. The Server's own coverage is proved in crates/platpulse-server/src/http/public.rs (fourteen cases around :3849-4467: a series nobody observed, a window that holds nothing while the series has been seen, the ledger dating a series whose samples expired, a future instant that may not date a series, a counted silence with its bounds and kind, the same silence named inside a short window once the cadence is its own floor, a changed cadence answered as unknown rather than as silence, a measured zero that stays evidence, a window that holds observations it does not contain, a recovered series whose silence is named once the next observation settles the rhythm, a backfilled block dated by its observation rather than by its height, a block series no ledger can date once its rows expire, the absence of a block series the Server cannot prove answered as an unknown rather than as never observed, and the gap and the tail of every series in the nine-series order) plus two cases in crates/platpulse-server/src/metric_history.rs (`a_window_shorter_than_the_floor_is_judged_by_its_cadence_alone`, `a_silence_inside_a_short_window_is_a_gap_once_the_floor_is_the_cadence`); ### 15.27 Home toolbar entries: the Sort & filter and Search surfaces (issue #232, delivered)

Applies to `PAGE-HOME-NETWORKS` (`/`), on top of §15.23 (which owns the search, the Health and Validator status filters, and the ordinary Home URL) and §15.24 (which owns the card/list View control and the sort keys, nine of them since §15.31):

- The row keeps one entry per concern, and the controls an entry hides are not in the row. The toolbar (platpulse-web/src/components/HomeToolbar.tsx) reads Network (the pill row, one tab stop; the arrow keys move between the pills) → the search control (§15.30's two shapes, in the place §15.33 gave it) → `Sort & filter` → the card/list View control (an independent tab stop of its own). The Health select, the Validator status select, the Sort select and the search field are not in the row at all: with both surfaces closed the row holds no `combobox`, no `searchbox` and no `dialog`, and the walk from the selected pill reaches those four stops in that order and nothing else — a hidden control is never left in the tab walk, because that is what "hidden" has to mean for a keyboard reader. The `Sort & filter` entry is a `Button` (`data-slot="home-filter-trigger"`, `aria-label="Sort & filter"` — the name it keeps whatever its own text track prints (§15.34) — `aria-haspopup="dialog"`, `aria-expanded`) and the Search entry is an icon-only `Button` (`data-slot="home-search-trigger"`, `aria-label="Search Active Nodes"`, `aria-haspopup="dialog"`, `aria-expanded`) drawn by the same `lucide-react` line-icon set and with the same rounding and 44x44 box as the View control beside it: a monochrome line icon, never an emoji, never a glyph of its own. Focus is never trapped: a press outside a surface closes it without moving focus, and Escape closes it and hands focus back to the control that opened it (`returnFocusRef`).
- One surface at a time, anchored under its own control, and never a centred modal. Both surfaces are the one component platpulse-web/src/components/ui/toolbar-popover.tsx (`role="dialog"`, `data-slot="toolbar-popover"`, labelled `Sort and filters` and `Search Active Nodes`, which is also how a reader reaches them by role): `position: absolute` with `top: full` and `mt-2` inside the entry's own `relative` wrapper, so a surface hangs below the control that opened it, the toolbar behind it keeps its exact geometry (opening one moves no other button and reflows no row), and no backdrop ever covers the reading under the toolbar. The Home caller adds `md:relative md:shrink-0` to each wrapper and lifts the wrapper that owns the open surface: the wrapper carries `md:z-30` while its own surface is open and the resting `md:z-10` once it is closed, because the surface's own `z-30` is confined to its wrapper's stacking context while the cards the surface hangs over participate in the root one — their own positioned children (a health marker, a card's info button, a tooltip at `z-20`) sit out there at `z-10` and `z-20` and would otherwise paint through an open surface by document order alone, since equal z-indices are resolved by document order and the cards come later. The lifted level stays below the Radix dialog tier (`z-50` in platpulse-web/src/components/ui/dialog.tsx), so a dialog still covers a surface, and the control that opened the surface is inside the lifted wrapper, so it is never the control left behind. The sticky Home header outranks the lifted tier as well: platpulse-web/src/layouts/HomeLayout.tsx carries `sticky top-0 z-40` (raised from `z-10` by this ticket) so a row, or the surface hanging off its entry, that is scrolled up into the header band passes under the brand, the theme toggle and the Admin link instead of painting over them, while the `z-50` dialog tier still covers both. The surface is measured after layout and corrected into the viewport's own width (`VIEWPORT_MARGIN = 16`): a control near the right edge, or a viewport narrower than the surface (which is 288px for the `Sort & filter` surface, and 288px at `w-72` with 320px from the sm breakpoint at `sm:w-80` for the search surface), shifts the surface left instead of pushing the page sideways, and the correction is re-measured on resize — so opening a surface adds no primary horizontal overflow at 360x800, 390x844, 768x1024, 1280x800 or 1440x900. Opening the search surface focuses its field, and on a phone-height viewport the browser may scroll the page by the few pixels needed to reveal that field: the row itself neither reflows nor moves (the acceptance reads the row's geometry in document coordinates for exactly this reason, and the document height does not change), and no other control is displaced. The correction is horizontal only: a surface is never flipped above its entry or re-placed vertically, so on a viewport shorter than the room the entry leaves under itself (the phone-height case, where both surfaces reach past the fold) the reader scrolls the page to the surface's tail, and the acceptance scrolls the tail control — the Validator status select while no status filter is on, the `Clear filters` action while one is (§15.34) — into view and reads the hit test there instead of claiming that every edge of a surface fits the fold at rest. Which edge of its trigger a surface hangs from is the caller's choice (`align`, platpulse-web/src/components/ui/toolbar-popover.tsx): the default start edge, or the end edge for a trigger whose own width can change while it stays in the row, because the right-hand group is pinned to the row's right edge and a wider trigger would otherwise slide that surface sideways as the reader changes what the trigger states (§15.34). The anchor belongs to the control and not to the surface: the search entry keeps the default start anchor, since its own width never changes.
- An entry states the state the row cannot show it. The `Sort & filter` entry draws `data-slot="home-filter-count"` with the number of status filters that are off their defaults — counting exactly the two choices behind the entry (`health !== 'all'` plus `validator !== 'all'`, so 0, 1 or 2) and never the Network selection, the sort order, the view or the search text, each of which says its own state elsewhere. The chip is drawn only while that number is not zero (§15.33): a live count paints the accent chip, and at zero the entry carries no chip at all, because a chip reading `0` states nothing — the entry's own name and the described-by sentence below still tell every reader that nothing is filtering. The chip is `aria-hidden="true"` and decorative — the entry's accessible name stays `Sort & filter` — and the same number always reaches a reader who cannot see it as a description of that entry: `aria-describedby="home-status-filter-count"` on the entry plus a `sr-only` span (`#home-status-filter-count`) reading `<n> of 2 status filters on` (`0 of 2 status filters on` at zero). The surface prints the same sentence beside its own clear action, but only while it draws that action at all: the footer — sentence and action together — exists only while a status filter is on (§15.34), so at zero a reader is never told about a filter that is not on and is never handed an action drawn disabled. The order in force is stated the same way: the entry's one fixed-width text track (`data-slot="home-filter-sort"`, decorative, `aria-hidden`) prints the entry's own name at rest and `Sort: <short name>` while the Sort control is off its own `Health` default — the word from the lg breakpoint, where the row has the room for it, and never at the cost of a width of its own — and the entry describes itself through a second `sr-only` sentence (`#home-sort-state`, `Sort is <key label>: <direction>.`) joined to the same `aria-describedby`, so the order reaches every reader at every width and is never counted as a status filter (§15.34). The Search entry carries `data-search-state="on"` while `queryText` is not blank — closed or open — with a drawn marker (`data-slot="home-search-active"`) beside the icon in addition to the accent border and text, so an active search is never read through colour alone, and while it is active the entry describes itself through a `sr-only` span (`#home-search-state`) reading `Search is on: <the query>`. Marker and attribute are state, and neither changes an accessible name.
- `Clear filters` resets the two status filters and nothing else. One ordinary URL write sets `health` and `validator` to `all`, so the sort order, the search text and the Network selection stay where the reader put them (§15.23's "only a reader action rewrites the link" holds: this is a reader action and it undoes its own two choices, not the whole link), and the surface stays open while the reader works in it. It is drawn only while at least one status filter is on, together with the sentence beside it (§15.34): with both status filters at `all` the surface draws no footer at all, so an action that has nothing to undo is never drawn disabled for a reader to wonder about, and the action appears exactly when there is something to reset. `Clear search`, inside the search surface, clears only the query (`query: ''`, `replace: true`) and leaves the rest of the link alone.
- The search surface keeps §15.23's own text contract: the field is the same labelled `role="searchbox"` with the same `queryDraft` keystroke handling, full width inside the surface and one fixed track from the sm breakpoint. Opening the surface focuses the field, because typing is the reason it was opened; a surface of choices (`Sort & filter`) leaves focus on the control the reader just used rather than moving it into the panel.
- No new dependency, no new route, no new Server surface. The popover is built in-repo on the existing dismissal idiom rather than on a popover dependency: a capture-phase `pointerdown` listener and an `Escape` key listener, both removed in the effect's cleanup, as platpulse-web/src/components/ui/data-tooltip.tsx already does (platpulse-web/src/components/GeoWorldMap.tsx:163 closes on `Escape` the same way) — §7 lists the stable semantic `PATTERN-*` IDs and defines no dismissable-surface pattern, `HOME_PARAMETERS` and the filters module are unchanged, and this ticket adds no `PAGE-*`, no `PATTERN-*`, no `SCN-*` and no API.
