### Node Detail composition (PAGE-HOME-NODE)

This user-approved unified contract supersedes the earlier Validator-four-KPI / ordinary-six-KPI compositions. It is a presentation target, not a claim of implementation or test completion. All Nodes share the same 1280px shell and reading order: Header → six KPIs + Node Peer Country View → Chain state / Process / Host resources → optional Validator performance → Latest 60 seconds → optional Validator diagnostics. Only Validator performance is role-conditional; no duplicate page, blank placeholder, Public API expansion or Home/Admin change is authorized.

1. **Shared Header.** Keep the uncarded heading, the `Back to Home` back context that returns the reader to the reading and the Node they left (§15.25), the Server-owned Node Health dot before the display name, and the exceptional health reason. The compact metadata line shows sync state, an evidence-backed role, applicable Validator Activity and inline relative Last report, for example Current · Validator · Active · 1s ago or Current · Observer · 1s ago. Health, sync, staking validity, Activity and Provider freshness remain independent. Do not repeat routine Active/Current in performance; retain abnormal stale/error evidence. Full Node UUID and copy-full-ID control sit below in muted monospace. Exact report UTC is available through the inline title or accessible explanation, not a separate right-hand block.
2. **Role and performance eligibility.** Only currentValidatorStatus=validator renders performance, including a retained stale-positive verdict with an explicit last-confirmed/stale warning. Display Observer only for currentValidatorStatus=not_validator with currentValidatorStatusState=current; it is a presentation alias for confirmed non-Validator status, not an independently observed role or consensus-membership inference. Unknown, missing Link and stale-negative evidence omit the unproven role and render no performance. Identity/status reasons and available identity facts stay visible beside the affected displayed values rather than implying a role. An effective automatic Node Validator Link corresponds to this Node's own Network-scoped chain identity; it does not prove current staking validity or another Node's role. Candidate/Locked/Exiting Activity does not replace the role. Preserve Activity source/time/reason semantics; the Home Observing fallback is not evidence of an Observer role.
3. **Six KPIs and one map track.** Both roles use Head, Sync collection, Peers, Uptime, Block interval and Transactions / block, in that order, with identical padding, typography, tabular values and equal heights. Use three columns by two rows from sm and two columns on phones. From lg, the KPI grid and map occupy approximately 5:6 tracks; the map keeps Home's band (proportional 2:1 below xl, the fixed 22rem band from xl) and, as on Home, the six KPIs keep their natural height bottom-aligned to that band rather than stretching to fill it, so the map is never squeezed to the KPI stack height. Below lg the map leads the band visually, exactly as on Home, while the KPIs-then-map DOM order is unchanged; both sit on the contained proportional track. Geometry never depends on role. Preserve the uncarded map's Peer markers/clusters, country information, counts, tooltips and local degradation. Map and Peers share the Node-scoped current_node_peers denominator, without IP deduplication, Peer identities or claims about Node deployment location. Disabled/never-observed/stale/unusable states retain an honest map track, not a fabricated zero or healthy map. The second tile is titled `Sync collection` because `syncState` is the state of the sync-data collection, not a chain-sync verdict: it keeps the real Current / Error / Unknown wording (never `Synced`), carries no standing caption in its normal state, and puts the full definition in an on-demand info hint in the tile's existing marker slot (the shared summary card is unchanged, so Home does not move). Only the Unknown state keeps a visible reason caption.
4. **Shared Chain state.** Show published valid absolute QC Head, Locked Head, Committed Head, Observed Head and Network Head values, plus Head lag when comparison is supported; omit missing optional rows rather than filling the card with Unknown. Network Head means the deployment-local Server Observed Network Head, not an independently established public-chain head. Head lag = Observed Network Head − Node Head: 0 reads At network head with success colour; 1–10 reads 1 block behind / N blocks behind with warning; greater than 10 uses error. Negative values are explicitly ahead, never clamped to zero. Head/Sync comparison captions share the valid-current/high-confidence gate; missing, invalid, stale or low-confidence input makes no equality, progress or health claim. Without an API expansion, this conservatively requires valid heights, a valid receipt timestamp, rpcState=ok, Server health=healthy and high reference confidence; no browser TTL is invented. Retain annotated last-good absolute heights. Membership and component diagnostics are not restated as Validator True/False or unknown resync rows.
5. **Shared Process and Host resources.** Process shows Collection as Successful / Error / Disabled / Unsupported / Starting / Unknown, Started as absolute UTC, and available Data directory (the Node data directory size against its filesystem capacity) / Data usage; uptime belongs in its KPI only. Collection describes the last collection, not present-tense Running/Stopped: Public data lacks process-specific existence/freshness evidence, and collection error does not prove a stopped process. Hide optional missing start/storage/usage rows; never invent capacity or percentage. Process CPU/memory stay in charts rather than repeated prominent static metrics. Host resources retains CPU, Memory and Storage fine progress tracks, plus one Network row with ↑ upload / ↓ download and no track. Keep the collected-once-per-Agent/shared-Host explanation and distinguish Node Data from whole-Host storage, but as on-demand definitions rather than standing small print: an info hint beside the Host resources title (collected once per Agent, shared by every Node it monitors), beside Collection (latest collection result, not a live Running/Stopped status) and beside Data usage (directory size against its own filesystem, not whole-Host disk usage). An info hint (`components/InfoHint.tsx`) is a real 44px button opening a small dialog surface — tap, click, Enter or Space open it; a press outside, the button or Escape close it, and Escape returns focus — never a bare `title` or hover-only tooltip. Only static definitions move into hints; actual conditions (collection failed, stale, Unknown, a missing direction) stay visible as short text. All three panels share padding, title baseline, row spacing and dotted separators; grid/flex spacing aligns heights without filler. They sit side by side from lg and stack below it.
6. **Compact Validator performance.** One compact card, not six large cards, contains desktop three-column/two-row metrics: Cumulative blocks / Cumulative rewards / Network rank, then Production rate / PlatScan 24h rate / Reward share. Narrow screens reflow without clipping. These remain the six existing lifetime/count/reward/rank/rate metrics; Reward share means effective delegation reward distribution ratio, not commission or yield, with the full meaning accessible. Preserve full integer counts, real zero, Unranked, Not applicable and independent missing/last-good states. The first row (Cumulative blocks / Cumulative rewards / Network rank) is the primary tier at 17px semibold; the second row (the three rates) is a lighter 13px tier. Rates display at most two decimals with insignificant trailing zeros removed (`100.047221` → `100.05%`, `75.50` → `75.5%`, a non-zero value below the last place → `<0.01%`), rounded half-up on the decimal string by `formatRatePercentCompact` (`lib/rate.ts`) — never through floating point, never clamped at 100%, and with the source value itself unchanged; the full-precision value stays reachable as the value's `title` and in the diagnostics footer. Overview rewards may retain the existing source-string four-fractional-digit presentation; exact source precision remains accessible in diagnostics, without floating-point rounding or invented digits. Use muted captions/tabular values, no repeated identity/status header, large icons or reserved blank height. Target roughly 50–60% of the prior normal Linked Validator card height without clipping warnings/controls. Missing optional metrics do not become zero or a wall of Unknown. End with the abbreviated Validator ID and its copy/reveal controls; the Validator diagnostics disclosure is its own region after the six-chart deck (item 7), so expanding it never displaces the metrics. The new name reflects same-identity correspondence; Home Linked Validator naming is unchanged.
7. **Identifiers and diagnostics.** Keep full Node ID copy and full Validator identifier copy/reveal accessible by keyboard, pointer and touch. Validator copy failure announces failure and exposes selectable complete text, never false success. Preserve full accessible control names, focus and 44×44 targets. The Validator diagnostics disclosure reuses the native details/summary recipe, defaults collapsed and lives in its own region after the six-chart deck; expanded, it reads as three key/value groups — Identity & activity (staking status/state/qualifier, identity state, activity/state), Source & freshness (provider state, data freshness, last success, source, source cutoff) and Ranking & counters (rank state/freshness/last success/cohort, counter state, production rate state) — three columns from lg, two from sm, one on phones, label left and value right with long values wrapping, no nested scroll and no merged `All healthy` verdict; a compact footer below the groups holds the full-precision cumulative rewards and rates as selectable text. It is gated by the same conditional-performance eligibility; ineligible Nodes get no standalone Validator diagnostics or blank slot. Agent/binary versions, RPC or debug fields absent from Public Projection are not added or fetched from Admin to fill it. Identity uncertainty reasons and independent Provider/rank failures, relevant stale/counter warnings and exceptional Node Health stay visible beside affected displayed values while collapsed.
8. **Shared six-chart deck.** (This item describes the Live Metric Window; §15.38 / ADR 0012 adds the `1h · 6h · 24h · 7d` windows on top of it (issue #247) without changing anything stated here for Live.) Preserve real latest-60-second response bounds (from, to, windowSeconds) and identical ordering: Process CPU / Process memory / Host network, then Peer connections / Block interval / Transactions / block. First four are lines, last two bars. Cards, headers and plots align; current values sit top-right and legends at the bottom, not beside titles or mixed with realtime values. Block-number context is muted. Keep existing colours, units, tooltips and labelled direction series. A hover tooltip states each sample with its own instant; a percentage, count or duration sample is printed as retained (no one-decimal pre-rounding, three decimals as the display cap), while a byte-rate sample is read on the same binary ladder and decimals as the card header and the `Speed (…)` axis title — `80.4 KiB/s`, `148 KiB/s`, and `800 B/s` below 1 KiB — never as a bare byte count such as `151618 B/s` (issue #249; Emerald deviation 39). A direction the reader hides from a legend stays hidden across live refreshes, resizes and Light/Dark switches, and a failed refresh keeps the last drawn window under a `Retained 60-second window` heading with one short failure notice (§15.26). Each header keeps the unit its own current value carries where that value sits top-right, exactly as Emerald's does (its CPU card prints `12.5` and `%`, its network card a chevron-up and chevron-down with `2.00 KiB/s`), while the unit is stated once more on the value axis's own title — `CPU (%)`, `Memory (%)`, `Speed (MiB/s)`, `Duration (s)` — never on a tick and never as a second label beside the title; the printed `Upload` / `Download` small text is the accessible name of each direction reading rather than a second line under the numbers, and both readings share one row. Grid: one column below md, two from md, three from xl. The plot is the ECharts-mounted container (`data-slot="node-metric-chart"`): 132px on phones, 168px from md and 192px from lg — deviation 30 in the Emerald migration register supersedes the earlier "plot AND SVG: 7.25rem/6.25rem" wording, and deviation 33 supersedes deviation 30's own 116/148/176 heights. The 60-second window is named by clock labels on the time axis itself, each card's 16px bold title is the largest reading on the card while the current value stays a 12px reading in the header's right corner, and a byte-rate axis is written in the single unit its own peak-derived ceiling chose. CPU/memory retain dynamic ceilings selected from observed samples — 5/10/25/50/100/150/200/250/400% — never a fixed 100% for low utilisation and never rescaled samples, so a Process CPU above 100% keeps its own ceiling instead of being clamped to 100. The ladder rung is the target of that ceiling search, not the ceiling itself: a rung that no step a reader counts in can divide (700%, whose fifth is 140) is passed to the lowest whole-step ceiling above it (750% at 150%) instead of collapsing the axis onto its floor and its ceiling. The plot's own height, less its margins and an optional legend, decides how many tick bands its labels can space 14px apart — five at 192px and at 168px, three in a 132px phone plot that also carries a legend — so a shorter plot prints fewer ticks rather than overlapping them. Whole-number series (Transactions / block and every block count) draw whole-number ticks without repeating a tick label; a series with no valid observation states its empty state instead of a flat line, and no run is ever joined across a Server-judged silence.
9. **Observation and clock integrity.** Lines may use the Server's last-good point before the window; bars use only in-window observations. No intermediate samples, mock data or missing-value zeros. Failures degrade only affected series and retain unrelated/last-good values. Two-summary history supplies only the consecutive-block interval; missing/non-consecutive summaries remain unavailable. No Bounded Block History, History Gaps, Validator analytics or history export is added. Last report ticks each visible-page second, pauses while hidden and recomputes on return; its display clock never refetches or changes domain freshness/health/chart windows, nor announces every tick. Invalid/missing times remain unavailable; future timestamps retain an explicit clock warning, not fake 0s ago.
10. **Pinned Emerald surfaces.** Keep existing system font, compact spacing, restrained radius, muted secondary text, light separators, chart colours and status/accent tokens. Summary surfaces use bg-background/60, observation/performance/chart surfaces bg-background/50, disclosures bg-background/40, static without decorative shadows, lift or opacity-hover changes. Map remains uncarded. Controls retain feedback/focus. No new dashboard style, palette, gradients, large icons or Home/Admin changes.
11. **Role-switch acceptance.** Switching confirmed Validator/Observer changes only role metadata and adds/removes performance. Header, six KPIs, map, three panels and chart composition retain widths, ordering and breakpoints. Charts naturally move vertically by the added region's height, with no role-specific map/KPI jumps or invisible placeholders.

The dashboard presents independent observation dimensions. One failed collection must not hide or rewrite another dimension, and one Agent's Nodes must never be merged into an Agent-level chain view.

### State and realtime acceptance

The UI keeps collection state, freshness state, value state, and authorization state independent. It renders the fixed user-facing vocabulary from this document: Starting, Current, Stale, Error, Unknown, Disabled, Unsupported, Empty, Connecting to live updates, Live updates paused, and You are offline.

- Initial route loads show a meaningful Starting/loading state and do not fabricate values.
- A successful observation may show Current or an authoritative empty value. A successful Peer Snapshot/aggregate of zero is displayed as zero, not Unknown; omitted/unsupported peer collection remains distinct.
- An Error or Stale observation may retain LastGood data, but the UI must show the error/stale reason and age/freshness supplied by the Server. It must never convert Unknown, stale, never-observed, Disabled, or Unsupported into 0, false, or Healthy.
- Node, history, metric-history, and validator requests fail independently. A failed optional module does not erase the Node summary or unrelated successful modules.
- A normal SSE invalidation preserves the currently displayed Node and view context while the exact Public resource is refetched. A reset, authorization transition, Node ID change, or access recheck clears affected sensitive projection state before the next render and may show a revalidation state.
- SSE carries invalidation/reset signals only. REST remains authoritative for all displayed business values. A disconnected stream announces Live updates paused; an open stream announces nothing, because the positive transport state is silent; browser-offline state may additionally announce You are offline.
- Retired, deleted, forbidden, or unknown public Nodes use non-leaking unavailable copy and never reveal whether a protected record exists.

### Theme behavior (Issues #146–#148)

The production theme lifecycle is a shared foundation, not a per-page option. It applies to public Home, the public Node Detail, Login, Admin direct entry, and reloads. Issue #146 delivered the lifecycle, the shared foundation, and the Login adaptation; Issue #147 completed the public Home and Node Detail adaptation as a visual-only slice; Issue #148 completed the Admin workbench and management-flow adaptation on the same foundation. Admin keeps its quiet undecorated workbench background and never adopts the public grid.

- **Three modes.** One control cycles Auto → Light → Dark → Auto. Its accessible name states the current choice and the action it performs (for example, "Theme: Auto. Switch to Light"), it is a 44×44 CSS-pixel target, and it keeps visible keyboard focus. Auto is the default when no valid preference exists.
- **Auto follows the system live.** A change to the operating-system preference takes effect immediately while Auto is selected. An explicit Light or Dark choice is never overridden by a system change.
- **Persistence is preference-only.** The selection is stored under a production-owned key (`platpulse.themeMode`) and is isolated from the throwaway prototype key. A missing or invalid value falls back to Auto; unavailable storage must not prevent in-session switching. The preference survives reload and cross-route navigation.
- **First paint is pre-mount.** The resolved theme, canvas, and browser `color-scheme` are applied by a synchronous same-origin head script (`public/theme-init.js`) before the application module runs, and reconciled when React mounts. It is external rather than inline because the Server enforces `script-src 'self'`. This must hold on direct entry and reload of Home, Login, and Admin, and must not depend on a post-mount correction.
- **Shared surfaces.** Dark mode overrides the shared shell tokens and the shared shell, cards, forms, tables, navigation, and Login surface; semantic warning/error/success/unknown styling stays distinct rather than inverted, and color alone never carries status.
- **Login.** Login keeps the fixed Emerald reference at commit `c2c5e88ea19c7cbe18d14a50414e10deca3cc66e` and the accepted A calibration: coordinated light/dark neutrals, the near-#141923 dark canvas, and the actual SVG grid geometry with layered masks rather than an approximate CSS line gradient, including the full-bleed width deviation defined under "Visual language" above.
